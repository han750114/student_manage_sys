## 建議規則

1. 五份 JSON 的最外層均為清單，初始內容為 []。
2. 選課關係以 enrollments.json 為主要來源；學生已選課程、總學分、課程剩餘名額由它計算。
3. 所有資料透過函式參數傳入；核心函式不呼叫 input()，由 main.py 處理互動。
4. 代號使用字串；課程代號、學號、教室代號、活動代號各自不得重複。
5. 星期為整數 1～7，節次為字串，排序固定為 1、2、3、4、5、6、7、8、9、a、b、c。
6. 課程時段分別記錄教室；教室透過 building_id 對應未來校園圖的節點。
7. 時間區間採 [開始, 結束)，結束恰好等於下一個開始時，不算時間重疊；移動時間另行檢查。
8. 活動使用實際日期與時間。產生課表必須指定查詢週，不能把一次活動顯示在每一週。
9. 發現整份 JSON 損壞時應顯示錯誤並保留原檔；單筆不合法資料應列出位置與原因，避免整個程式異常終止。
10. 使用者操作失敗時不修改原資料；存檔應避免寫到一半留下損壞檔案。

## 預計介面

| 模組 | 輸入 | 輸出 |
|---|---|---|
| storage.load_records | 檔案路徑 | (資料清單, 錯誤清單) |
| storage.save_records | 檔案路徑、資料清單 | 成功無回傳值；失敗由呼叫端處理例外 |
| validation.validate_course | 課程、教室資料 | 錯誤字串清單 |
| validation.validate_student | 學生資料 | 錯誤字串清單 |
| management.add_course | 原課程清單、新課程、教室清單 | 含 ok、data、errors 的結果字典 |
| management.find_courses | 課程、篩選條件、選課紀錄 | 符合條件的課程清單 |
| conflicts.check_enrollment | 學號、課程代號、系統資料、節次實際時間（有活動時） | 含 ok、data、errors；data 含全部衝突與學分／剩餘名額 |
| conflicts.add_enrollment | 同上 | 含 ok、data、errors；成功 data 為新的選課清單，由呼叫端先存檔再更新記憶體 |
| timetable.build_timetable | 學號、系統資料、查詢週星期一日期、節次實際時間 | 含 ok、data、errors；data 為 12 列節次 × 7 欄星期課表 |

系統資料 data 預計為含 students、courses、classrooms、activities、enrollments 的字典。

## 尚待決定

- 學期起訖、假日及十二個節次的實際時間（F2、F4、F9 共用）。
- 教室可用時段與設備名稱格式；若未來支援跨午夜活動，須另行調整本次限制。
- 本次跨日空閒查詢採逐日列出連續空節，不把兩天串成一段；上課前後可查詢，但不列入課間空堂統計。
- 刪除學生、活動取消、課程改時段時，關聯資料如何更新。
- 必修清單、評分公式與權重、重新規劃時保留原課表的優先順序。
- 載入無效紀錄後，哪些操作應禁止存檔，避免遺失原資料。
